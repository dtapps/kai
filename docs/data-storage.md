# 数据存储

> status: 有效 · last_verified: 2026-10-27 · 基线 `de28c9e`（master）

三个 SQLite：`config.db`（引擎配置）、`history.db`（翻译历史）、`httplog.db`（HTTP 请求日志）。都放在 `~/.kai/data/`（开发态 `~/.kai.dev/data/`）。路径规则见 `internal/buildinfo/buildinfo.go`，配置字段见 `configuration.md`，凭据加密见 `security-privacy.md`。

## 1. 总览

| 数据库       | 包                      | 写入方                      | 读方                       | 清理             |
|--------------|-------------------------|-----------------------------|----------------------------|------------------|
| `config.db`  | `internal/configstore`  | 设置页引擎增删改、迁移      | 引擎注册、历史页引擎名回填 | 手动删库/删行    |
| `history.db` | `internal/historystore` | 翻译成功后写入              | 历史页                     | 手动删除/清空    |
| `httplog.db` | `internal/httplogstore` | 所有经包裹 Transport 的请求 | 排障时手工查               | 每小时清理过期行 |

驱动：默认 `modernc.org/sqlite`（纯 Go）；`-tags sqlite_mattn` 切 `mattn/go-sqlite3`（CGO）。DSN 由 `internal/sqlite` 生成，带 `foreign_keys`、`journal_mode=WAL`、`busy_timeout=5000`（mattn 用 `_foreign_keys` / `_journal_mode` 语法）。

## 2. Schema

### 2.1 `config.db`

```sql
CREATE TABLE IF NOT EXISTS engines (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    engine   TEXT    NOT NULL UNIQUE,
    enabled  INTEGER NOT NULL DEFAULT 0,
    api_key  TEXT    NOT NULL DEFAULT '',
    secret   TEXT    NOT NULL DEFAULT '',
    extra    TEXT    NOT NULL DEFAULT '',
    endpoint TEXT    NOT NULL DEFAULT ''
);
```

- `engine` 唯一：每个引擎类型一行，不支持同类型多账号。
- `api_key` / `secret` 落库前 AES-GCM 加密，密文前缀 `kai:cipher:`；读取时解密。
- `extra` 存 JSON（LLM 的 `model` / `timeout_sec`，OCR 的 `langs` / `correct_text` / `timeout_sec` / `retry_count`）。
- `enabled` 只是启用态；运行时注册表由 `EngineWrapper.registerEngines()` 重建。

### 2.2 `history.db`

```sql
CREATE TABLE IF NOT EXISTS history (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    text       TEXT    NOT NULL,
    result     TEXT    NOT NULL,
    from_lang  TEXT    NOT NULL DEFAULT '',
    to_lang    TEXT    NOT NULL DEFAULT '',
    engine_id  INTEGER NOT NULL DEFAULT 0,
    from_ocr   INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_history_created ON history (created_at DESC);
```

- `created_at` 是**毫秒时间戳**（`time.Now().UnixMilli()`），不是秒。
- `engine_id` 引用 `config.db` 的 `engines.id`，**跨库无外键**；引擎被删后历史仍在，历史页会把引擎名显示为空。
- 写历史前按 `(text, engine_id, from_lang, to_lang, from_ocr)` 去重（`FindDuplicate`），完全相同的翻译不重复入库。
- 查询按 `created_at DESC`，关键词同时匹配 `text` 与 `result`。

### 2.3 `httplog.db`

```sql
CREATE TABLE IF NOT EXISTS http_log (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    hostname            TEXT,
    method              TEXT,
    url                 TEXT,
    request_headers     TEXT,
    request_body        BLOB,
    status_code         INTEGER,
    response_headers    TEXT,
    response_body       BLOB,
    elapse_time         BIGINT,
    process_elapse_time BIGINT,
    is_error            BOOLEAN NOT NULL DEFAULT 0,
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    go_version          TEXT,
    plugin_version      TEXT
);

CREATE INDEX IF NOT EXISTS http_log_hostname ON http_log (hostname);
CREATE INDEX IF NOT EXISTS http_log_method ON http_log (method);
CREATE INDEX IF NOT EXISTS http_log_url ON http_log (url);
CREATE INDEX IF NOT EXISTS http_log_status_code ON http_log (status_code);
CREATE INDEX IF NOT EXISTS http_log_created_at ON http_log (created_at DESC);
```

- append-only：常驻连接只 INSERT；DELETE 由 Cleanup 用临时连接执行。
- 请求/响应头以 JSON 文本存储；请求/响应体只在非空时写入，并会把字面量 `\uXXXX` 解码成正常文本。
- **可能包含敏感信息**（Authorization 头、请求体中的文本）。默认 `http_log.enabled=true`、保留 30 天；不需要时在 `settings.json` 关掉，或定期清理。

## 3. sqlc 生成

每个 store 目录一套：

```text
internal/<store>/
├── schema.sql      # 建表
├── migration.sql   # 增量迁移（configstore 没有，迁移在 Go 里）
├── query.sql       # 命名查询
├── sqlc.yaml       # sqlc v2 配置
├── db.go           # 生成：DBTX / Queries
├── models.go       # 生成：行模型
├── querier.go      # 生成：接口
└── query.sql.go    # 生成：实现
```

生成：

```bash
make sqlc
# 实际执行
cd internal/historystore && sqlc generate
cd internal/configstore && sqlc generate
cd internal/httplogstore && sqlc generate
```

约定：

- 生成文件头是 `// Code generated by sqlc. DO NOT EDIT.`，不要手改。
- 改查询改 `query.sql`，改表改 `schema.sql`，然后 `make sqlc`。
- 三个 `sqlc.yaml` 都开 `emit_json_tags`、`emit_interface`、`emit_empty_slices`；httplog 额外开 `emit_pointers_for_null_types`。
- `sqlc` 版本由 CI Dockerfile 的 `ARG SQLC_VERSION=v1.31.1` 固定；本地版本不同可能生成不同代码，提交前看 diff。

## 4. 迁移

### 4.1 启动顺序

`configstore.Open`：

1. `sql.Open` + `PRAGMA journal_mode=WAL / busy_timeout=5000 / foreign_keys=ON`；
2. 执行 `schema.sql`（`CREATE TABLE IF NOT EXISTS`）；
3. `MigrateSecrets`：把旧明文 `api_key` / `secret` 加密写回，已带 `kai:cipher:` 前缀的跳过；
4. `MigrateEngineNames`：把历史 `engine='system'` 改为 `engine='apple'`。

`historystore.Open`：

1. `sql.Open`，`SetMaxOpenConns(1)`；
2. 执行 `schema.sql`；
3. 逐条执行 `migration.sql`，忽略 `duplicate column` 错误（SQLite 不支持 `ADD COLUMN IF NOT EXISTS`）。

`httplogstore.Init`：

1. 仅 `enabled=true` 时打开 DB；
2. 执行 `schema.sql` 与 `migration.sql`，同样忽略 `duplicate column`；
3. 接管 `http.DefaultTransport`，让第三方库的裸 `http.Get` 也入库。

### 4.2 加字段

- `history.db`：在 `internal/historystore/migration.sql` 追加 `ALTER TABLE ... ADD COLUMN ...`，不要改 `schema.sql` 的历史定义（新库会先建表再跑迁移，重复 ALTER 会被忽略）。
- `httplog.db`：同上，当前 `migration.sql` 只有注释示例。
- `config.db`：没有 `migration.sql`；在 `schema.sql` 改表后，需要在 `Store.Open` 里加 Go 迁移（参照 `MigrateSecrets` / `MigrateEngineNames`），保持幂等。
- 加完字段后 `make sqlc`，再改 `EnginesToConfig` / 查询映射。

### 4.3 迁移的边界

- 迁移只做「加列 / 改名 / 加密」这类可重复执行的操作，没有版本表；不要写不可重入的 DDL。
- 不自动删列、不自动重建表。需要重建时让用户删库（见 §6）。
- 迁移失败会阻止应用启动（`configstore.Open` / `historystore.Open` 返回错误，`main.go` `log.Fatalf`）。

## 5. 跨库引用

```text
history.engine_id  ──(无 FK)──>  config.engines.id
```

- 引擎删除不会级联删除历史；`HistoryWrapper.GetHistory` 找不到引擎时 `engine` 为空串。
- 不要试图在 SQLite 里给两个独立 DB 建外键；SQLite 不支持跨库 FK。
- 备份/恢复时三个库要一起处理，否则历史里的 `engine_id` 可能对不上。

## 6. 检查、清理、备份

### 6.1 检查

```bash
sqlite3 ~/.kai/data/config.db 'select id,engine,enabled from engines order by id;'
sqlite3 ~/.kai/data/history.db 'select count(*), min(created_at), max(created_at) from history;'
sqlite3 ~/.kai/data/httplog.db 'select count(*), max(created_at) from http_log;'
```

### 6.2 清理

```bash
# 退出 Kai 后
sqlite3 ~/.kai/data/httplog.db 'delete from http_log;'
sqlite3 ~/.kai/data/httplog.db 'vacuum;'

# 清空历史（保留表结构）
sqlite3 ~/.kai/data/history.db 'delete from history;'
```

`httplogstore.StartCleanup` 每小时按 `http_log.retention_days` 删过期行；`retention_days<=0` 时不清理。

### 6.3 备份

```bash
# 退出 Kai，确保 WAL 已合并
sqlite3 ~/.kai/data/config.db 'pragma wal_checkpoint(truncate);'
cp ~/.kai/data/*.db ~/backup/kai-$(date +%F)/
```

`config.db` 的凭据绑定本机设备指纹，备份到另一台机器只能恢复 `engine` / `enabled` / `endpoint` / `extra`，`api_key` / `secret` 解不出来，需要重填。

### 6.4 重置

```bash
# 失联/损坏时全量重置
rm -rf ~/.kai/data
```

下次启动重建三个库与默认引擎。注意 `~/.kai/settings.json` 不会删；如果要连界面偏好一起重置，删整个 `~/.kai`。开发态对应 `~/.kai.dev`。

## 7. 已知边界

- `config.db` 的引擎行是「类型级」的，不支持同一引擎多账号；需要多账号只能换引擎类型或外部代理。
- `history.db` 没有自动清理/容量上限；长期使用会持续增长，目前只能手动清空。
- `httplog.db` 记录的是明文请求/响应（可能含 API Key 与翻译文本），且默认开启；对隐私敏感的用户应关闭。
- HTTP 日志开关是 `sync.Once` 初始化，运行中改 `http_log.enabled` 不会生效，必须重启。
- 没有数据库加密（除 `config.db` 的两个凭据列）；历史与 HTTP 日志是明文 SQLite。
