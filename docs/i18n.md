# 国际化（i18n）

> status: 有效 · last_verified: 2026-10-27 · 基线 `de28c9e`（master）

Kai 有**两套完全独立**的 i18n：

- 后端 `internal/i18n`：go-i18n v2，管托盘、通知、日志、错误、更新器。
- 前端 `frontend/src/i18n`：自研 TS 字典，管界面文案。

还有**两套完全独立**的语言码：

- `Locale`（界面语言）：`auto` / `zh-CN` / `en-US`，用于 UI、托盘、通知。
- `Language`（翻译语言）：`auto` / `zh` / `en` / `ja` / ...，用于翻译请求、历史记录。

不要互转，也不要把 `zh-CN` 塞进翻译语言，或把 `zh` 塞进界面语言。

## 1. 后端 i18n

### 1.1 文件结构

```text
internal/i18n/
├── i18n.go                 # embed、SetLocale、T、TWithLocale、ResolveLocale
├── error.go                # Error 类型 + 不可见信封 + ParseError / TranslateError
└── locales/
    ├── zh-CN.json          # 合并产物，勿手改
    ├── en-US.json          # 合并产物，勿手改
    └── split/
        ├── zh-CN/
        │   ├── app.json        # app.* / window.* / notification.*
        │   ├── engine.json     # 引擎展示名
        │   ├── errors.json     # err.*
        │   ├── lang.json       # lang.*
        │   ├── logs.json       # log.*
        │   ├── menu.json       # menu.*
        │   └── messages.json   # 当前 0 个 key（预留）
        └── en-US/（同结构）
```

当前合并产物各 **302 个 key**（含合并脚本注入的 `_comment`）。

### 1.2 合并

```bash
make i18n-go
# 等价于 ./scripts/merge-go-i18n.sh（Windows 为 .cmd）
```

脚本逻辑（`scripts/merge-go-i18n.sh`）：

1. 对 `split/<locale>/*.json` 用 jq `reduce .[] as $f ({}; . * $f)` 深度合并；
2. 注入 `_comment`，提示「此文件自动生成」；
3. 按 key 排序后写入 `locales/<locale>.json`。

`internal/i18n/locales/*.json` 被 `//go:embed` 进二进制，所以合并后必须重新编译才能生效。热重载只改后端 `SetLocale`，不会重读 JSON。

### 1.3 查找与回退

- `T(key, k1, v1, ...)`：按当前 locale 查；找不到回退 `zh-CN`；再找不到返回 key 本身。
- `SetLocale` 只认 `en-US`，其它一律落到 `zh-CN`（`internal/i18n/i18n.go`）。
- `TWithLocale` 临时切 locale，用于需要指定语言的场景。
- 模板参数用 `{{.Name}}`，调用示例：

```go
i18n.T("app.name_version", "Version", buildinfo.Version)
i18n.T("log.data_dir", "Dir", dataDir)
```

### 1.4 错误信封

`i18n.Error` 的 `Error()` 返回：

```text
<已翻译文本> \x1f <key> \x1f <JSON 参数>
```

`\x1f` 是 U+001F（不可见），用于前端解析后按自己的语言重新翻译。相关函数：

- `i18n.NewError(key, ...)` / `i18n.Wrap(err, key, ...)`：构造。
- `i18n.ParseError(s)`：解析出 key/params/原文。
- `i18n.TranslateError(err)`：取不含信封的文本，**日志/落库必须用它**，否则会把控制字符写进数据库。

当前前端没有调用 `ParseError`，实际显示后端已翻译文本；接前端翻译时再统一接入。

## 2. 前端 i18n

### 2.1 文件结构

```text
frontend/src/i18n/
├── zh-CN.ts            # 基准字典，导出 Dict 类型
├── en-US.ts            # 英文，类型必须与 Dict 一致
├── index.svelte.ts     # t() / locale / setLocale / resolveLang / langName / engineName
├── index.ts            # 统一出口
└── index.test.ts
```

- `zh-CN.ts` 是**类型基准**：`export type Dict = typeof zh`。新增 key 先加中文，再补英文；`en-US.ts` 的 `Dict` 类型会强制对齐。
- `t(path, params)` 用点号路径（如 `t('settings.general')`），参数用 `{name}` 占位。
- 查不到时返回 path 本身，方便发现漏 key。
- `langName(code)` / `engineName(code)` 把语言码/引擎名映射为展示名，找不到时原样返回。

### 2.2 语言解析

- `resolveLang(lang)`：`zh-CN` → 中文，`en-US` → 英文，`auto` 用 `navigator.language` 判断（`zh*` → 中文，其余英文）。
- `getSystemLocale()` 只看 `navigator.language`，不调后端。
- 主题/语言切换通过 `setLocale` 写 runes 状态并同步 `locale` store。

### 2.3 `make i18n-frontend` 当前是 no-op

`scripts/merge-frontend-i18n.sh` 期望的目录是 `frontend/src/locales/split/`，但仓库里**没有这个目录**，脚本对缺失目录直接 `return 0` 并打印 `done.`。因此：

- 前端文案当前直接改 `frontend/src/i18n/zh-CN.ts` / `en-US.ts`；
- `make i18n-frontend` 不会生成任何文件，不要指望它；
- 若以后恢复 split 方案，先建 `frontend/src/locales/split/<locale>/*.json`，再把 `index.ts` 的导入改为生成物。

## 3. 新增文案

### 3.1 后端

1. 在对应 split 文件加 key（按前缀归类：`err.` / `log.` / `menu.` / `app.` / `window.` / `notification.` / `lang.` / `engine.`）。
2. 两个 locale 都加，key 必须一致。
3. `make i18n-go`。
4. 代码里用 `i18n.T("key", ...)`；错误用 `i18n.NewError` / `i18n.Wrap`。
5. `go test ./internal/i18n/`。

### 3.2 前端

1. 在 `zh-CN.ts` 的对应嵌套对象加 key，再在 `en-US.ts` 加同路径。
2. 组件里 `import { t } from '../i18n'`（路径按层级调整），用 `t('a.b.c')`。
3. 需要参数时用 `t('key', { name: value })`，字典里写 `{name}`。
4. `pnpm test`（`index.test.ts` 会检查语言解析与缺失 key 行为）。

### 3.3 新增界面语言

当前只支持 `zh-CN` / `en-US`。只加 JSON/TS 字典**不会生效**，必须同时改这些白名单：

1. `internal/model/model.go` 的 `Locale` 常量。
2. `internal/i18n/i18n.go` 的 `Locale` 常量、`SetLocale`、`ResolveLocale`。
3. `internal/settings/service.go` 的默认值与 UI 下拉选项。
4. 前端 `frontend/src/constants/lang.ts` 的 `Lang` 与 `LangCode`。
5. 前端 `frontend/src/i18n/index.svelte.ts` 的 `dicts`、`resolveLang`、`getSystemLocale`。
6. 更新器 `pkg/wails-updater-providers/i18n.go` 的 `i18nMessages` 与 `consts.go` 的 `localeAliases`（独立的一套文案表）。
7. 两套字典文件 + 合并后端 JSON + `make i18n-go`。

漏掉第 2 或第 5 步，表现是「JSON 加了但界面还是中文/英文」。

## 4. 前后端对齐

| 场景          | 后端                   | 前端                                      |
|---------------|------------------------|-------------------------------------------|
| 托盘/菜单     | `i18n.T("menu.*")`     | —                                         |
| 窗口标题      | `i18n.T("window.*")`   | `document.title` 由 HTML 写死，不随语言变 |
| 设置页        | 错误信息用 `i18n.T`    | `t('settings.*')`                         |
| 翻译/OCR 错误 | `err.*` + `i18n.Error` | 展示后端文本（暂不解析信封）              |
| 日志          | `log.*`                | `frontend.log` 写原文                     |
| 更新窗口      | 更新器包内 `T()`       | 更新器内嵌 HTML 模板                      |

已知不一致：

- `app.name_version` 等后端 key 用 `zh-CN` 文案；`language: auto` 时后端只落到 `zh-CN`（`i18n.SetLocale` 白名单），所以英文系统 + auto 时托盘可能仍是中文。前端界面则按系统语言显示。见 `configuration.md` §2.3。
- 前端 `events.ts` 里 `LocaleChangedPayload` 的注释写 `zh/en`，实际 `ConfigWrapper.SaveConfig` 把 `mode` 与 `language` 都填成配置值（可能是 `auto`）；以代码为准，前端展示前需 `resolveLang`。
- 后端 `messages.json` 目前为空；新增通知类文案放这里或 `app.json`，不要新建无引用的文件。

## 5. 死 key 检查

仓库没有自动死 key 检查。需要时用下面两条手工核对：

```bash
# 后端：代码里引用过的 i18n key
grep -rhoE 'i18n\.T\("[^"]+"' internal pkg main.go | sed 's/i18n.T("//' | sort -u > /tmp/used-keys.txt
# 后端：合并后的全部 key（去掉 _comment）
jq -r 'keys[]' internal/i18n/locales/zh-CN.json | grep -v '^_comment$' | sort -u > /tmp/all-keys.txt
comm -13 /tmp/used-keys.txt /tmp/all-keys.txt   # 只在字典、未被引用的 key
```

前端：

```bash
grep -rhoE "t\('[^']+'" frontend/src --include=*.svelte --include=*.ts | sed "s/t('//" | sort -u
```

注意：动态拼接的 key（如 `lang.${code}`、`engine.${name}`）会被误报为未使用，人工确认后再删。
